## 已实施方案依据：APK 安全区、紧凑词卡与词本长按菜单

状态：用户已确认实施，并进一步明确取消“清空词本”，只删除目标词本；完成情况以上方 2.0.20 交付记录为准。

### 第 1 步：统一原生窗口安全区

- 下方的系统区域是导航栏或手势导航条。当前 APK 已有原生语音/登录桥接，Capacitor SystemBars 默认提供安全区处理，但应用把留白分散在 main、navbar、body 和面板样式中；尚不能仅凭静态代码确认用户报告遮挡的具体触发状态。
- 以 Android WindowInsets（状态栏、导航栏、刘海与键盘）为统一依据，让 APK 内容区域、抽屉和长按菜单都在安全区内布局。原生容器与网页 CSS 必须明确由一处承担系统留白，避免重复计算。手机网页继续使用浏览器安全区。
- 保留系统栏，不强制沉浸隐藏；系统返回键优先关闭菜单/弹窗，再返回词本列表。
- 核验正常打开、顶部导航展开/收起、输入键盘、长按菜单和底部操作区域；先修安全区再评价可用屏幕高度。
- 依据：[Android 16 edge-to-edge 行为](https://developer.android.com/about/versions/16/behavior-changes-16#edge-to-edge)、[Capacitor SystemBars](https://capacitorjs.com/docs/apis/system-bars)。

### 第 2 步：压缩词库/词本详情的单词列表卡片

- 手机实测系统字体缩放为 1.25。当前词卡由单词/音标头部、释义色块、例句色块、操作行组成，重复容器内边距与段落间距会叠加高度；因此主要压缩结构，不继续压低已经很小的例句字号。
- 建议词头约 18–20px，音标 11–12px，释义约 13px；短词的音标与词头并排，长词自然换行。外边距/内边距统一约 8–10px，段落间距约 6px。
- 去掉释义与例句内的多层独立色块/边框；保留整张卡片作为层级边界。释义默认摘要最多两行，可显式展开完整释义；例句默认收起，以“例句”入口展开英文和译文。展开不能与原有朗读点击行为混淆。
- “标记掌握”等单词操作可移到头部右侧，保留足够触摸区域。卡片高度随内容变化，不靠固定高度裁掉内容。
- 目标是常见短词卡片明显变矮；屏幕能显示几张仍受释义长度、展开状态和用户字体缩放影响，不保证固定张数。

### 第 3 步：详情只留测试动作，管理功能移入词本长按菜单

- 修改前 `handleClearAllWrongWords` 清空全局 wrongWords；`handleClearAllMasteredWords` 清空全局 masteredWords。登录时会发起对应的云端删除。它们不按当前列表/词本限定，也不清空 customWordLists 或内置资源；本轮已移除这两个回调及全部清空入口。
- 详情页保留返回、搜索、排序与“测试词本”，移除导入、导出、清空及词本删除工具栏；测试动作与详情标题放在同一行，减少首屏占用。
- 词本入口长按约 450–500ms 弹出主题一致的圆角操作卡片，参考 LightNote 的触发方式及 PageTrace 的菜单样式：图标加文字、约 48–56px 操作行、危险操作红色。滑动时取消长按，长按后的抬手不进入详情；遮罩点击和系统返回键关闭菜单。
- 自定义及内置词本：按用户最新要求只提供“删除词本”，删除卡片和该词本成员关系；其他词本中的相同单词及共享学习记录保留。确认框显示词本名与数量。
- 内置词本通过持久化删除 ID 排除用户词本入口；原始资源保留用于 APK 默认四级测试。全量、顽固、近期等系统分组是筛选视图，不提供删除分组。
- 已通过隔离测试验证删除范围，未使用用户手机进行删除试验。

## 当前实现与原因

源码位于 `repos/english-word-master/`，APK 通过 Capacitor 打包同一套 React 前端。以下为源码检查结果，尚未经手机视觉验证。

- `src/components/Navbar.tsx`：导航为 sticky，手机顶部内容区高度为 h-14；三个模块入口在汉堡抽屉内。
- `src/components/QuizView.tsx`：外层 ProgressBar 与卡片内题号重复；手机在初次载入及换题时自动滚动到外层进度锚点。
- `src/index.css`：手机外层进度条也设为 sticky，因此导航和进度叠加占用顶部空间；测试区域最小高度按当前导航高度计算。
- `src/components/QuizView.tsx`：测试词为 text-4xl，卡片内边距 p-6、内容间隔 space-y-6、选项 p-4；例句为文字块与不可收缩的按钮并排，右侧列占据整段英文和译文的宽度。
- `src/components/ui/WordCard.tsx`：官方词库与词本共用词卡，可在 APK 范围内统一收紧。当前手机词头 1.65rem、释义 text-base、例句 text-sm。
- 手机根字号为 15px。测试词约 33.75px、选项和例句约 13.1px，不能把 text-sm 误认为手机上固定 14px。

## 已实施方案

### 1. 顶部导航与测试进度

以 Android 原生运行环境限定本次样式和交互。初次打开导航完全收起，保留系统状态栏安全区；页面向下滚动即显示导航，短页面通过同方向手势唤出。抽屉打开时保持导航状态稳定，程序换题引起的自动滚动不应误触发导航显示。

移除 APK 卡片外进度显示；同步将自动滚动锚点改为测试卡片，调整顶部偏移和测试区域最小高度。仅用 CSS 隐藏原锚点会留下错误的滚动依赖。

测试页上方的大标题、徽标和介绍也建议收起，避免导航和进度去掉后仍留下介绍卡占据首屏。词库和词本保留紧凑标题及必要操作。

### 2. 三个页面的文字和留白

建议初始字号：测试词 30px，四个选项 13px，英文例句 12.5px、译文 12px、音标 12px；词库/词本的词头 20–22px、释义 13–14px；页面标题 18px。已足够小的统计和辅助说明不继续整体缩小。

测试卡内边距由约 22.5px 调至 14–16px，主要内容间距由约 22.5px 调至 12–16px，选项内边距调至 10–12px、间隔 8px。手机四个选项仍纵向排列，长释义自然换行。例句行高约 1.4–1.5，完整展示而不截断。

词库压缩标题区、搜索区、目录卡和单词卡留白；词本压缩标题区、子标签、操作区和单词卡留白。按钮保留至少 40px 的有效触摸区域，文字变小不等于按钮难点。

### 3. 例句与朗读按钮

首选：将“朗读例句”按钮移到现有答题反馈行右端，下面英文和中文各自占满内容宽度。复用现有反馈行，不新建一整行例句工具栏。喇叭图标约 16px，点击范围至少 40px，提供明确的“朗读例句”标签。

反馈文字保持紧凑；必要时将掌握进度解释改成简短展示，但保留正确/错误、掌握次数和生词本状态。不使用覆盖文字的绝对定位，也不再给整段例句预留右侧按钮列。

### 4. 实施后的必要验证

检查初次打开、向下滚动显示导航、短页手势、回顶部隐藏、抽屉操作、换题及答题后的滚动状态；确认卡片内题号始终存在。检查常见手机宽度下的长单词、长选项、英文例句和中文译文，以及词库与词本的主要操作。完成相关类型检查和前端构建后，再构建、验证 APK。
